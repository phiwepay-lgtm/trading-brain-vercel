# Chart research workspace

The existing dual-pane chart retains its drawing and journal features. It defaults to BTCUSD and requests at least 2,000 M1 and 5,000 M5 candles in the background, subject to provider history and limits. The same selected provider is used for every page. Short or unavailable history is reported instead of being filled with another source. Twelve Data pagination is paced, but quotas and entitlements may still limit coverage. Binance BTCUSDT is a USDT proxy, not BTC/USD spot; the demo feed is deterministic simulated data. None of these feeds is an MT5 connection.

## Data and overlays

The active workspace's candles are held in an in-memory Zustand store. The optional translucent M5 HA overlay on M1 may include an unfinished M5 candle, but the candidate replay uses only completed M5 candles and completed standard M1 candles. HA is seeded from the first loaded M5 bar; loading earlier history can change the seed and values. The pivot markers use configurable left/right widths and the tester draft's asymmetric equality rules. A marker is displayed on its original pivot candle **after** its right-hand candles close; it was not knowable on that candle. Active high and low annotations show the replay tracker's independent FTB expectations. Session shading illustrates proposed New York 09:30–16:00 local and Asia 01:00–06:00 UTC, not verified journal times. Session filtering defaults to bypass; turning it on also requires confirmation in the panel. Shading is independent of that filter.

## Candidate replay

The browser replays the loaded overlapping candles. The tester-style mirrored bearish BT rule was explicitly selected: a close below the latest fresh M5 HA pivot low, with the signal low and latest fresh HA high as fib anchors. A new setup resets earlier setup state; ambiguous simultaneous candidates do not produce an entry. FTB requires a true HA touch within the configured penetration bound and bypasses the BT fib filter. M1 VHB/VLB and engulf checks use raw M1 candles, not HA. Events are plotted at M1 bar-open timestamps but become observable at that bar's close; reaction and CHoCH cannot occur on the same bar, and entry must be at least 120 seconds after CHoCH. A user-entered tick size is an assumption, not broker metadata. Edge mode gates entries, not shared setup detection: disable FTB separately for a cleaner BT-only split.

This is a **research implementation**, not a verified MQL execution or Pine equivalence. The tester source is uncompiled. The replay seeds HA once from the loaded array, whereas the tester draft obtains a rolling history window; startup, skipped events, limited M1/M5 overlap, broker prices, tick size, timezones and platform behavior can differ. There is no broker connection or order placement. Diagnostics and candidate events are not executed trades or journal verification.

## Optional candle simulation

The simulation is opt-in. It consumes the generated candidate list independently of positions; it assumes a signal-close entry, one position at a time, and ignores candidate entries while a position is open. Exits use subsequent M1 OHLC only. When both stop and target occur inside one bar, stop wins; opening gaps execute at the next candle open. Positions spanning a missing M1 interval are censored rather than assigned a fictitious result, and open positions are excluded from closed-trade metrics. No spread, slippage, fees, margin, contract sizing, intrabar path, or tick data is modeled. The equity curve and statistics are simulated R, not verified performance, and demo results describe simulated prices. This is not an MT5 or TradingView broker-emulator backtest.

## CI and deployment

The GitHub workflow runs the strategy-JavaScript lint scope, TypeScript, unit tests, production build and browser tests on PRs and main. It does not lint the entire existing TS/TSX application. The existing Vercel Git integration is linked to `main` and has separately produced production deployments. It is independent of the workflow: **CI does not gate Vercel deployment**. No production deployment of this branch has been made; a main merge requires explicit authorization. No Vercel secrets or raw journal data are stored in the repository.
